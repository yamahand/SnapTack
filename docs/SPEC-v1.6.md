# SnapTack 仕様書 追補 (v1.6) — 保存強化とスクラップ作成方法の追加

本書は SPEC.md (v1.0) / SPEC-v1.x.md (v1.1〜v1.4) / SPEC-v1.5.md (v1.5) への追補である。
既存の仕様は特記なき限り維持する。

対象マイルストーンは `MILESTONES-v1.6.md` の **M18 (保存とコピーの強化)** と
**M19 (スクラップの作成方法の追加)**。機能の根拠は `SETUNA2-gap-analysis.md` を参照。

## 1. 目的と背景

v1.5 までで、スクラップは「管理対象のデータ」へ格上げされた (SPEC-v1.5 1)。
一方で **外へ出す手段 (保存・コピー)** と **中へ入れる手段 (作成)** は v1.0 当時のまま狭い。

| 課題 | 現状 | 本版での解決 |
|---|---|---|
| 保存形式が PNG のみ | 写真系の画像でもサイズの大きい PNG しか選べない | JPEG / BMP を追加 (M18) |
| 保存が必ずダイアログ経由 | 連続して保存したい時に毎回フォルダとファイル名を確定させる必要がある | 即保存 (日時で自動命名) を追加 (M18) |
| 保存したファイルを他アプリへ渡しにくい | パスを手で辿る必要がある | 保存後にパスをクリップボードへコピーするオプション (M18) |
| 作成経路がキャプチャのみ | 既に手元にある画像をスクラップにできない | クリップボード / ドラッグ&ドロップからの作成 (M19) |

コンセプトの「情報の一時保持」は維持する。本版は **保持しているものの出し入れ** を広げるだけで、
スクラップそのものの性質 (物理ピクセル等倍・加工しない。SPEC 4.4) は変更しない。

## 2. M18: 保存とコピーの強化

### 2.1 保存形式

保存形式を **PNG / JPEG / BMP** の 3 種から選べるようにする。

| 形式 | 拡張子 | エンコーダ | 備考 |
|---|---|---|---|
| PNG | `.png` | `PngBitmapEncoder` | **既定**。可逆。現行の挙動 |
| JPEG | `.jpg` | `JpegBitmapEncoder` | 非可逆。品質を指定できる |
| BMP | `.bmp` | `BmpBitmapEncoder` | 無圧縮。SETUNA2 互換のため用意する |

- いずれも `System.Windows.Media.Imaging` の標準エンコーダで実装する。**外部 NuGet は追加しない**。
- JPEG の品質は設定項目 `JpegQuality` で指定する。範囲 **1〜100、既定 90**。
  - `JpegBitmapEncoder.QualityLevel` へそのまま渡す。範囲外の値は保存時にクランプする。
- **アルファチャンネルの扱い**: JPEG / BMP は透過を保持しない。ただしキャプチャ画像は
  画面のコピーであり実質不透明なので、変換は行わず**そのままエンコーダに渡す**。
  付箋の不透明度 (SPEC-v1.x 2.2) が出力に影響しないのは現行どおり (元画像を保存する)。

#### ダイアログ保存 (既存の「保存...」) の変更

現行の「PNGで保存...」を **「保存...」** に改める (形式が PNG 固定でなくなるため)。

- `SaveFileDialog` のフィルタに 3 形式を並べる。**既定の選択は設定の `SaveFormat`** とする。
- ダイアログ上で形式 (フィルタ) を切り替えた場合、**その選択が保存形式になる**。
  拡張子が形式と食い違う場合は、`SaveFileDialog` の `AddExtension` に任せて
  選択フィルタの拡張子を補う。**ユーザーが明示的に付けた拡張子は尊重する** —
  すなわち「入力された拡張子が 3 形式のいずれかに一致するなら、その形式で保存する」。
  - 理由: `.jpg` と手入力したのに PNG が書かれる、という不一致を避ける。
- 既定ファイル名は `SnapTack_yyyyMMdd_HHmmss.<拡張子>` (現行と同じ規則、拡張子のみ形式に追従)。
- 既定の保存先は現行どおり `LastSaveDirectory` → 「ピクチャ」の順 (SPEC-v1.x 2.1)。

### 2.2 即保存 (ダイアログ無し)

**ゴール: ダイアログを出さずに、指定フォルダへ日時名で 1 アクション保存する。**

- 保存先は設定項目 `QuickSaveDirectory`。**未設定なら「ピクチャ」を使う**
  (即保存を初回から使えることを優先する。フォルダ未設定を理由に機能を止めない)。
- ファイル名は `SnapTack_yyyyMMdd_HHmmss.<拡張子>`。形式は設定の `SaveFormat` に従う。
- **同名ファイルが既にある場合は `_2`, `_3` … と連番を付けて衝突を避ける**。
  上書きは行わない (ダイアログ無しで既存ファイルを壊さない)。
- 保存先フォルダが存在しない場合は**作成を試みる**。作成に失敗したら保存失敗として扱う。
- 保存に成功しても**ダイアログや通知は出さない**(即保存の意義が失われるため)。
  失敗時のみ従来どおり MessageBox で通知する。
- `LastSaveDirectory` は**更新しない**。即保存の保存先はダイアログの前回フォルダとは別の概念とする。

#### 起動方法 (要判断だった項目 → 決定)

**付箋の右クリックメニュー項目 + 付箋ローカルのショートカットキー `Ctrl+Shift+S` とする。**

- グローバルホットキーは**追加しない**。
  - 理由: グローバル登録は失敗リスク (他アプリとの衝突) と設定項目を増やす。加えて
    「どの付箋を保存するか」の対象決定が曖昧になる。付箋にフォーカスがある状態でのみ
    効くローカルキーなら対象が一意に決まる。
  - SETUNA2 も枠付き保存を `Ctrl+Shift+S` に割り当てており、キー選択の整合も取れる。
- スクラップリストのコンテキストメニューにも「すぐ保存」を追加する。
  こちらは**選択中の全件**に対して実行する (一括保存できることに実用価値があるため)。
  - ダイアログ保存 (`保存...`) はリストでも現行どおり**先頭 1 件のみ**とする
    (ダイアログを選択数ぶん連続で出すのは煩わしいため。現行挙動の維持)。

### 2.3 保存したファイルパスのコピー

- 設定項目 `CopyPathAfterSave` (既定 **false**) を追加する。
- true の場合、保存成功後にそのファイルのフルパスを `Clipboard.SetText` でコピーする。
- **ダイアログ保存・即保存の両方に適用する**。
- 複数件を即保存した場合は、**保存できた全パスを改行区切りでコピーする**。
- クリップボードのロックで失敗しても**保存自体は成功しているので、警告は出さない**
  (`Clipboard.SetImage` と異なり、副次的な操作のため。SPEC 4.4 の「握りつぶさない」に対しては
  保存が成功している事実をユーザーが確認できるので実害がない)。

### 2.4 設定項目の追加 (M18)

| キー | 内容 | 既定 |
|---|---|---|
| `SaveFormat` | 保存形式 (`Png` / `Jpeg` / `Bmp`) | `Png` |
| `JpegQuality` | JPEG 品質 (1〜100) | 90 |
| `QuickSaveDirectory` | 即保存の保存先。未設定 (null) なら「ピクチャ」 | null |
| `CopyPathAfterSave` | 保存後にファイルパスをクリップボードへコピーするか | false |

- `JpegQuality` は設定画面で 1〜100 にクランプして保存する。
- `QuickSaveDirectory` は設定画面の**参照ボタン** (`OpenFolderDialog`) で選ぶ。手入力も可。

## 3. M19: スクラップの作成方法の追加

### 3.1 作成経路

キャプチャに加えて以下の経路を設ける。**いずれも生成は必ず `ScrapManager.Add` を経由する**
(中央管理を崩さない。SPEC-v1.5 3.1)。

| 経路 | 起動方法 |
|---|---|
| クリップボードの画像から作成 | トレイメニュー「クリップボードから貼り付け」 |
| クリップボードのテキストが画像ファイルパスなら、その画像から作成 | 同上 (同じメニュー項目が両方を扱う) |
| 画像ファイルの D&D | スクラップリストウィンドウへのドロップ |
| 画像ファイルの D&D | exe / トレイアイコンへのドロップ → **本版では非対応 (3.5 参照)** |

### 3.2 クリップボードからの作成

トレイメニューの 1 項目で以下を順に判定する。**最初に成立したものを採用する**。

1. `Clipboard.ContainsImage()` → その画像からスクラップを作る。
2. `Clipboard.ContainsFileDropList()` → 含まれるファイルのうち**対応拡張子のものすべて**を読み込む。
3. `Clipboard.ContainsText()` → テキストを**パスとして解釈**する。ファイルが存在し対応拡張子なら読み込む。
   - 前後の空白と、パスを囲む二重引用符 (`"C:\a.png"` 形式) を除去してから判定する。
   - 複数行のテキストは**各行をパスとして扱う** (エクスプローラーの「パスのコピー」で
     複数選択すると改行区切りになるため)。
4. いずれも成立しなければ**何もしない**(エラーダイアログは出さない。
   「貼るものが無かった」だけで警告を出すのは煩わしいため)。

- 対応拡張子は `.png` / `.jpg` / `.jpeg` / `.bmp` / `.gif` / `.tif` / `.tiff` /
  **`.webp` / `.avif`** とする。
- 読み込みに失敗したファイル (壊れている・デコードできない) は**読み飛ばす**。
  1 件も作れなかった場合のみ MessageBox で通知する。

#### webp / avif の扱い

`.webp` / `.avif` は **WPF (WIC) が追加コード無しで読める**ことを実機で確認した
(それぞれ `Microsoft Webp Decoder` / `Microsoft HEIF Decoder` が処理する)。
外部 NuGet の追加は不要。

ただしこれらのデコーダは **OS 標準ではなく Store の拡張機能パッケージ**
(`Microsoft.WebpImageExtension` / `Microsoft.HEIFImageExtension`) が提供し、
いずれも `NonRemovable: False` = **削除可能**である。したがって:

- **未導入の環境では読めない**ことを前提とする。読めた場合の上乗せ機能と位置づける。
- 未導入時に WIC は `COMException` を投げるため、`TryLoadFile` はこれを握って null を返す。
  結果として「読み飛ばし → 1 件も作れなければ通知」という既存の失敗経路に合流し、**アプリは落ちない**。
- 保存形式 (2.1) には **追加しない**。エンコーダが提供される保証がなく、
  「標準エンコーダのみ・外部 NuGet を追加しない」方針から外れるため。

`.heic` も同じ HEIF デコーダで読めるが、**本版では対象外**とする
(Windows 版では需要が薄い。将来 mac 対応を検討する際に併せて判断する)。

> **注**: クリップボードは他プロセスのロックで例外を投げるため、参照は try-catch で囲む
> (CLAUDE.md のコーディング規約)。失敗時は「貼るものが無かった」と同じ扱いにする。

### 3.3 ドラッグ&ドロップ

**スクラップリストウィンドウをドロップ先とする。**

- `AllowDrop=True` とし、対応拡張子のファイルを含む `FileDrop` のみ受け付ける
  (それ以外は `DragDropEffects.None` にしてカーソルで拒否を示す)。
- ドロップされた対応拡張子のファイルを**すべて**スクラップ化する。
- 読み込み失敗時の扱いは 3.2 と同じ (読み飛ばし。全滅時のみ通知)。
- **ゴミ箱タブを表示中でも受け付ける**。作られたスクラップは常に `Pinned` なので、
  ドロップ後は「スクラップ」タブへ自動的に切り替える (作った結果が見えないのを避ける)。

### 3.4 外部画像から作ったスクラップの扱い

外部画像はキャプチャ元の位置を持たないため、以下のように決める。

- **`PhysicalRect` の位置 (X, Y) は「マウスカーソル位置」とする** (要判断だった項目 → 決定)。
  - カーソルのあるモニタ上で、カーソル位置を付箋の左上として配置する。
  - 画面外へはみ出す場合は、既存の `ClampIntoCurrentMonitor` と同じ考え方で
    **カーソルのあるモニタ内へクランプする**。
  - 理由: ユーザーの注目点に出るため発見しやすい。中央固定だと大きい画像で画面を覆う。
- **`PhysicalRect` のサイズ (Width, Height) は画像の物理ピクセルサイズとする**。
  - キャプチャ由来と同じく物理ピクセル等倍で表示する (SPEC 4.4 を維持)。
  - **画像がモニタより大きい場合も縮小しない**。等倍表示の原則を崩さないため。
    はみ出した部分は画面外になるが、付箋はドラッグで動かせる。
    (縮小表示は M20「拡大縮小」の領域であり、本版では扱わない)
- `CapturedAt` は**スクラップを作成した日時**とする (元ファイルの更新日時ではない)。
  - 理由: 一覧の並び順は「SnapTack に取り込んだ順」であるべきで、古い写真を貼ると
    リストの末尾に埋もれるのは直感に反する。
- 永続化は既存の仕組みをそのまま使う。**画像は `scraps/<id>.png` として PNG で保存される**
  (元ファイルの形式に関わらず。`ScrapStore.SaveImage` の現行実装を変えない)。
  - 元ファイルへの参照は持たない。**取り込み後に元ファイルを消してもスクラップは残る**。

### 3.5 スコープ外 (M19 では実装しない)

| 項目 | 理由 |
|---|---|
| exe / トレイアイコンへの D&D | exe へのドロップはコマンドライン引数として渡るため、**二重起動時の挙動** (SPEC 4.1 「即終了」) の変更と、既存プロセスへの IPC が必要になる。これは実質的にコマンドライン対応 (ギャップ分析 4) と同じ設計判断であり、M19 の範囲を超える。トレイアイコンへのドロップは `NotifyIcon` が標準で D&D を受けないため、別途ウィンドウを介する仕掛けが要る。**両者ともコマンドライン対応と併せて別途検討する** |
| 付箋 (ScrapWindow) へのドロップ | ドロップ先として発見しにくく、既存のドラッグ移動と操作が干渉する |
| クリップボード貼り付けのグローバルホットキー | ホットキー登録数を増やす。トレイメニューで足りるかを v1.6 の実使用で見てから判断する |

## 5. 互換性・非機能

- **既存設定との互換性**: v1.5 以前の `settings.json` をそのまま読めること。追加キーは既定値で補う。
  既定値 (`SaveFormat=Png`、`QuickSaveDirectory=null`) により、**設定を触らないユーザーの
  保存体験は v1.5 と変わらない**。
- **`index.json` のスキーマは変更しない** (`SchemaVersion` は 1 のまま)。
  M19 で追加するスクラップも既存のエントリ構造で表現できる。v1.5 との相互運用性が保たれる。
- 操作体系の既存部分 (左ドラッグ移動 / `Ctrl+C` / `Ctrl+S` / 中クリック / 右クリックメニュー) は
  変更しない (SPEC-v1.x 4)。追加操作は既存と競合しないこと。
- 大きな画像 (例: 4K 全画面) を D&D しても、既存のキャプチャと同じ経路を通るため
  メモリ・描画の扱いは変わらない。`BitmapSource` は従来どおり `Freeze()` する。

## 6. 決定事項

着手前に判断が必要だった項目 (`MILESTONES-v1.6.md` の「要判断」) は以下のとおり確定した。

| 項目 | 決定 | 根拠 |
|---|---|---|
| 即保存の起動方法 | 付箋の右クリックメニュー + 付箋ローカルの `Ctrl+Shift+S`。グローバルホットキーは追加しない | 2.2 参照。対象が一意に決まり、登録失敗リスクと設定項目を増やさない |
| 外部画像の `PhysicalRect` | カーソル位置を左上とし、モニタ内へクランプ。サイズは画像の物理ピクセル等倍 | 3.4 参照。注目点に出るため発見しやすい |
| 保存形式の既定 | `Png` (現行維持)。JPEG 品質の既定は 90 | 既存ユーザーの体験を変えないことを優先 |
| 即保存フォルダ未設定時 | 「ピクチャ」へ保存する (機能を止めない) | 2.2 参照。初回から使えることを優先 |
