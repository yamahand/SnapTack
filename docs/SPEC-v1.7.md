# SnapTack 仕様書 追補 (v1.7) — スクラップの編集

本書は SPEC.md (v1.0) / SPEC-v1.x.md (v1.1〜v1.4) / SPEC-v1.5.md (v1.5) / SPEC-v1.6.md (v1.6)
への追補である。既存の仕様は特記なき限り維持する。

対象マイルストーンは `MILESTONES-v1.6.md` の **M20 (スクラップの編集)**。
機能の根拠は `SETUNA2-gap-analysis.md` 1 章・5 章を参照。

## 1. 目的と背景

v1.6 までで、スクラップの**出し入れ** (保存・コピー・作成経路) は SETUNA2 相当まで広がった。
残る最大の差分は **貼った後の加工** である。

| 課題 | 現状 | 本版での解決 |
|---|---|---|
| 大きすぎる / 小さすぎるスクラップを調整できない | 物理ピクセル等倍固定 (SPEC 4.4) | 拡大縮小 (2.2) |
| 向きの違う画像をそのまま貼るしかない | 加工手段が無い | 回転・反転 (2.3) |
| 選択をやり直すには取り直すしかない | キャプチャ時の範囲で確定 | トリム (2.4) |
| 位置の微調整がドラッグでしかできない | ドラッグのみ・座標が見えない | キー移動と移動値表示 (2.5) |

### SPEC 4.4 の改訂

`SPEC.md` 4.4 は **「付箋は画面キャプチャと同じ物理解像度で等倍表示する(拡大縮小しない)」**
と定めている。本版はこれを以下のとおり**改訂**する (`SPEC.md` 6 章が予告していた見直し)。

> 付箋は既定で物理ピクセル等倍で表示する。ユーザーが明示的に編集 (拡大縮小・回転・反転・トリム)
> を適用した場合に限り、その結果を反映して表示する。**編集していないスクラップの表示は
> v1.6 以前と完全に同一である。**

等倍は「不変条件」から「**既定値**」へ格下げする。自動的な縮小 (画像が大きいから縮める等) は
引き続き行わない — これは v1.6 で `AddExternal` に対して明示した判断 (`SPEC-v1.6.md` 3.4) と一貫する。
**倍率を変えるのは常にユーザーの明示的な操作**であり、アプリが勝手に変えることはない。

## 2. 機能仕様

### 2.1 編集モデル: 非破壊 (決定)

**元画像は保持したまま、変換パラメータを `ScrapItem` に持たせる。**
表示・コピー・保存の各時点で元画像へ変換を適用する。

| 案 | 判断 |
|---|---|
| **非破壊 (元画像 + 変換パラメータ)** | **採用** |
| 破壊的 (画像そのものを差し替え) | 不採用 |
| ハイブリッド (トリムのみ破壊的) | 不採用 |

採用理由:

- **劣化しない。** 拡大 → 縮小を繰り返しても元画像から 1 回変換するだけなので、
  再サンプリングの累積劣化が起きない。破壊的だと 150% → 50% で情報が失われる。
- **取り消せる。** 「編集をリセット」で必ず元へ戻せる (2.6)。トリムし過ぎても復旧できる。
- **画像ファイルを書き直さない。** `scraps/<id>.png` は追加時に 1 度だけ書く現行の規約
  (`SPEC-v1.5.md` 2.4) をそのまま維持できる。破壊的にすると編集のたびに画像を再保存する必要があり、
  保存失敗時に「表示は編集後・ディスクは編集前」という不整合を持ち込む。
- 代償は `index.json` のスキーマ拡張 (5 章) だが、これは既定値で吸収できる。

### 2.2 拡大縮小

- スケールは**パーセント**で保持する (`ScalePercent`)。既定 100。
- **範囲は 25%〜400%**。範囲外は操作時にクランプする。
  - 下限 25%: これ以上小さくすると内容が判別できず、サイコロ化 (48×48) の領域と重なる。
  - 上限 400%: SETUNA2 は 2 倍までだが、`NearestNeighbor` 補間ではドット単位の確認に
    もっと拡大したい場面がある (SnapTack の用途はエラーメッセージや資料の一部が中心)。
    無制限にしないのは、誤操作で画面を覆い尽くすのを防ぐため。
- ステップは **10%** (`Alt+↑` / `Alt+↓`)。**1%** の微調整を `Alt+Shift+↑` / `Alt+Shift+↓` に置く
  (SETUNA2 のキー割り当てに合わせる)。
- コンテキストメニューに **プリセット「400% / 200% / 100% / 75% / 50% / 25%」** を置く
  (不透明度プリセットと同じ形式。現在値にチェックを表示する)。
- **マウスホイールは使わない。** ホイールは既に不透明度に割り当て済み (`SPEC-v1.x.md` 2.2) であり、
  奪うと既存の操作体系を壊す (`SPEC-v1.x.md` 4「操作体系は変更しない」)。
- **補間方式は `NearestNeighbor` を維持する。** 現行の `ScrapWindow.xaml` の指定をそのまま使う。
  文字を含むスクリーンショットが主対象であり、ぼやけるより輪郭が残る方が読みやすい。

#### スケールの基準 (決定)

**物理ピクセル基準とする。** `ScalePercent = 100` は「画像の物理ピクセル等倍」を意味する。

- 既存の `SetWindowPos` による物理座標配置 (`ScrapWindow.OnSourceInitialized`) をそのまま使えるため。
  DIP 基準にすると、物理座標での配置と DIP でのスケールという**二重の基準**を持つことになる。
- SPEC 4.4 の等倍思想の素直な延長でもある (100% = 従来の見た目)。
- 異なる DPI のモニタへ移動した際の挙動は**現行どおり WPF の Per-Monitor V2 既定に任せる**
  (`SPEC-v1.x.md` 2.4 の判断を維持。DIP サイズが維持され物理ピクセル等倍は崩れる)。
  本版でこの挙動を変えることはしない。

### 2.3 回転と反転

- 回転は **90 度単位** (`RotationDegrees` ∈ {0, 90, 180, 270})。時計回りを正とする。
- 反転は**水平** (`FlipHorizontal`) と**垂直** (`FlipVertical`) の独立した真偽値。
- 適用順は **トリム → 回転 → 反転 → 拡大縮小** で固定する (2.7)。
- 90 / 270 度回転では**付箋の幅と高さが入れ替わる**。
  - 左上位置は維持し、そこから新しいサイズで展開する (サイコロ復元と同じ考え方)。
  - はみ出す場合は既存の `ClampIntoCurrentMonitor` でモニタ内へクランプする。
- キー: `R` で右 90 度回転、`Shift+R` で左 90 度回転 (SETUNA2 の `R` に合わせる)。
  反転はメニューのみとする (妥当な 1 文字キーが空いておらず、使用頻度も低い)。

### 2.4 トリム

**付箋上で範囲を再選択して切り出す。** 非破壊なので、切り出しは表示範囲の指定として保持する。

- `TrimRect` を**元画像の物理ピクセル座標**で保持する (null なら全体)。
- **モード切替が必要。** 通常時の左ドラッグは移動 (`SPEC.md` 4.4) であり、そのままでは干渉する。
  - コンテキストメニュー「トリム」または `T` キーで**トリムモード**に入る。
  - トリムモード中は付箋上に半透明の暗幕を重ね、ドラッグした範囲だけ明るく表示する
    (キャプチャオーバーレイと同じ見た目。`OverlayWindow` の表現を踏襲し、操作を学び直させない)。
  - **`Enter` で確定**、**`Esc` またはモード中の右クリックでキャンセル**する
    (SETUNA2 の「範囲指定 → Enter」に合わせる)。
  - トリムモード中は移動・サイコロ化・不透明度変更を受け付けない。
- 確定すると付箋のサイズが切り出し後のサイズになる。左上位置は維持する。
- **トリムは重ねがけできる。** 2 回目のトリムは 1 回目の結果に対する範囲指定として受け取り、
  内部では元画像座標へ合成して `TrimRect` を 1 つだけ保持する
  (パラメータが増えず、「編集をリセット」で必ず元へ戻せる)。
- 極小の選択 (数 px 未満) はキャンセル扱いとする (`SPEC.md` 4.3 と同じ判断)。
- **スケール適用後の見た目に対して選択させ、内部で元画像座標へ逆変換する。**
  ユーザーは見えているものを選ぶのであって、元画像の座標を意識しない。

### 2.5 キー移動と移動値の表示

編集とは独立した機能だが、微調整という目的が共通するため本版に含める。

- **方向キーで 1px、`Shift+方向キー` で 50px 移動**する (物理px。SETUNA2 と同じ刻み)。
  - 物理px 単位で動かすため、`SetWindowPos` による物理座標移動を使う。
    DIP で動かすと高 DPI モニタで「1px 押しても動かない / 2px 動く」が起きる。
- 移動中 (ドラッグ・キー移動の両方) は**付箋上に現在の左上座標を数値表示する** (物理px)。
  - 表示形式は `{0}, {1}` (言語非依存のため `const`)。
  - 表示位置は付箋の左上に重ね、半透明の背景を敷いて読めるようにする。
  - **操作が終わって一定時間 (1 秒) で消える。** 常時表示すると画像を隠すため。
- サイコロ状態でもキー移動は有効とする (`SPEC-v1.x.md` 2.3 の「サイコロ状態でも移動可」と揃える)。

### 2.6 編集のリセット

- コンテキストメニューに**「編集をリセット」**を置く。全変換パラメータを既定値へ戻す。
- 非破壊モデルの利点を UI に出す項目であり、**トリムし過ぎた場合の唯一の復旧手段**でもある。
- 編集が一切適用されていない場合は**淡色表示 (無効)** にする。

### 2.7 変換の適用順 (固定)

**トリム → 回転 → 反転 → 拡大縮小** の順に適用する。

- トリムを最初に置くのは、`TrimRect` を**元画像座標**で保持すると決めたため (2.4)。
  回転後に切ると、パラメータの意味が「どの時点の座標か」に依存して不安定になる。
- 拡大縮小を最後に置くのは、**再サンプリングを 1 回だけにする**ため。
  途中で拡大すると以降の変換が拡大後の画素に対して働き、劣化と計算量が増える。
- この順序は**実装の内部規約**であり、UI には出さない (ユーザーは順序を選べない)。
  順序を選べる仕組みは M21 (スタイル機構) の領域であり、本版では持ち込まない。

> **実装上の注意**: 回転と反転は `TransformGroup` にまとめるが、`Children` の順が
> そのまま適用順になるため **回転を先に追加する**こと。トリムの逆変換 (2.4) は
> 「反転を解いてから回転を解く」前提で書かれており、順序を入れ替えると
> **回転と反転を併用した時だけ**トリム位置がずれる。
> 実装中に実際に踏んだため、画素単位で往復を検証するテストを置いてある
> (`TrimRoundTripTests`)。座標計算だけのテストではこの取り違えを検出できない。

### 2.8 出力 (コピー・保存) への反映 (決定)

**編集結果を出力する。** `Ctrl+C` / 保存 / 即保存 のいずれも、**画面に見えているとおりの画像**
(2.7 の変換を適用した結果) を出す。

- 理由: 「見えているものが取れる」が直感的であり、**拡大して保存したい・向きを直して渡したい**という
  編集の主要な動機に応えられる。編集しても出力が変わらないなら、編集は見た目だけの機能に留まる。
- **不透明度と枠線は従来どおり出力に反映しない** (`SPEC-v1.x.md` 2.1 / 2.2)。
  これらは「付箋としての見せ方」であって画像の内容ではない。本版で変更しない。
  - SETUNA2 の「枠付きコピー / 枠付き保存」に相当する機能は**本版では入れない**。
    枠の種別自体が固定 (1px グレー) であり、選べるようになるのは M21 (フレーム種別) 以降。
- サムネイル (スクラップリスト・サイコロ) も**編集結果を反映する**。
  一覧と画面上の見た目が食い違うと、どのスクラップか判別できなくなるため。
- **`scraps/<id>.png` には元画像を保存し続ける** (非破壊の帰結)。
  出力時の変換適用はメモリ上で行い、ディスクの画像には触れない。

### 2.9 操作体系のまとめ

追加する操作は既存と競合しないこと (`SPEC-v1.x.md` 4)。

| 操作 | 動作 | 備考 |
|---|---|---|
| `Alt+↑` / `Alt+↓` | 拡大 / 縮小 (10%) | 新規 |
| `Alt+Shift+↑` / `Alt+Shift+↓` | 拡大 / 縮小 (1%) | 新規 |
| `R` / `Shift+R` | 右 / 左 90 度回転 | 新規 |
| `T` | トリムモードへ | 新規 |
| `Enter` / `Esc` | トリム確定 / キャンセル | トリムモード中のみ |
| `↑↓←→` | 1px 移動 | 新規。`Alt` 併用時は拡大縮小が優先 |
| `Shift+↑↓←→` | 50px 移動 | 新規 |
| 左ドラッグ | 移動 | **変更なし**。トリムモード中のみ範囲選択 |
| ホイール | 不透明度 | **変更なし**(スケールには使わない) |
| ダブルクリック | サイコロ化 | **変更なし** |
| `Ctrl+C` / `Ctrl+S` / `Ctrl+Shift+S` / `Ctrl+V` | コピー / 保存 / 即保存 / 貼り付け | **変更なし**(出力内容のみ 2.8 に従う) |
| 中クリック | 閉じる | **変更なし** |

`Alt+↑` と `↑` の競合は**修飾キーの有無で厳密に判定**して解決する
(`Keyboard.Modifiers` の完全一致で分岐する。既存の `OnKeyDown` と同じ書き方)。

> **実装上の注意**: **`Alt` を伴うキーは `KeyEventArgs.Key` が `Key.System` になり、
> 実際のキーは `SystemKey` に入る。** `Key` だけを見て分岐すると `Alt+↑` / `Alt+↓` が
> **一切反応しない**(実装中に実際に踏んだ)。判定前に
> `var key = e.Key == Key.System ? e.SystemKey : e.Key;` で解きほぐすこと。
> なお `Alt` 単独押下も `SystemKey=LeftAlt` として届くが、方向キー以外は分岐に載らないため無害。

### 2.10 サイコロ状態との関係

- **サイコロ化中は編集操作を受け付けない** (拡大縮小・回転・反転・トリム)。
  48×48 のタイルに対する編集は意味を持たず、UI も破綻する。
  該当メニュー項目は淡色表示にする。
- ただし**編集済みのスクラップをサイコロ化することはできる**。サムネイルは編集結果を表示する (2.8)。
- サイコロから復元した際は、編集後のサイズで展開する。

## 3. 設定項目

**本版で追加する設定項目は無い。**

- 拡大縮小の範囲 (25%〜400%) とステップ (10% / 1%)、キー移動の刻み (1px / 50px) はいずれも
  **定数とする**。設定化は項目を増やす割にユーザーが調整する動機が薄い。
- 必要性が実使用で確認できたら後から設定化できる (定数を設定へ移すのは容易)。

## 5. 永続化 (`index.json` のスキーマ拡張)

**編集状態は永続化する。** `SchemaVersion` を **1 → 2** へ上げる。

- 理由: 編集は不透明度・サイコロ状態 (これらも永続化済み) より**意図の強い操作**であり、
  再起動で失われると編集し直しになる。永続化しない選択は取らない。
- 追加するエントリ項目 (すべて省略可・既定値あり):

| キー | 型 | 既定 | 内容 |
|---|---|---|---|
| `ScalePercent` | int | 100 | 拡大縮小率 (25〜400) |
| `RotationDegrees` | int | 0 | 回転角 (0/90/180/270) |
| `FlipHorizontal` | bool | false | 水平反転 |
| `FlipVertical` | bool | false | 垂直反転 |
| `TrimRect` | object? | null | 元画像座標でのトリム範囲 (X/Y/W/H) |

### 書き込みのタイミング

**編集は適用後すみやかに `index.json` へ書く。** 不透明度・表示位置とは扱いを変える。

- 理由: 不透明度や位置は**すぐやり直せる**調整だが、編集 (範囲を選んでトリム・回転・倍率調整) は
  **やり直しの利かない意図的な作業**である。異常終了 (クラッシュ・強制終了・デバッガの停止) で
  失われると、ユーザーは同じ作業をやり直すことになる。
- `SPEC-v1.5.md` 2.4 の「ドラッグのたびには保存しない」は**連続的な**マウス移動による
  ディスク書き込みを避けるための判断であり、トリム確定や回転のような**離散的で意図的な**操作には
  当てはまらない。
- ただし `Alt+↑` の**キーリピートは連続的**なので、**短時間の連続編集は 1 回にまとめて書く**
  (最後の編集から 500ms 待ってから書き込む)。まとめ待ちの最中にアプリが終了する場合は、
  終了処理が予約分を書き切る。
- 実装は `IScrapView.EditApplied` → `ScrapManager` が受けて書き込む。
  **ビューはディスクに触れない** (永続化は Manager の責務。`SPEC-v1.5.md` 3.1)。
- 一覧のサムネイル・サイズ表示を追従させる `Changed` 通知は、
  **永続化の有無と無関係に**必ず発火させる。

### 互換性

`ScrapStore.Load` は現在 **`SchemaVersion != CurrentSchemaVersion` なら空で起動する**
(未知スキーマを解釈しない安全側の判断。`SPEC-v1.5.md` 2.4)。これを以下のように改める。

- **v1 の index は読める。** 追加項目を既定値で補って v2 として扱う。
  すなわち「編集していないスクラップ」として復元され、**v1.6 以前と同じ見た目になる**。
  読み込み後の保存で v2 へ書き換わる。
- **v2 より新しいスキーマは従来どおり空で起動する** (未来の形式は解釈しない)。
- **v1.6 以前のアプリで v2 の index を読むと空になる** (未知スキーマ扱い)。
  これはダウングレード時の既知の制約とし、リリースノートに明記する。
  - 画像ファイル (`scraps/<id>.png`) は残るため、データそのものは失われない。

`PhysicalRect` は**キャプチャ元の位置・サイズ**であり、編集後のサイズはそこから計算できるため
**変更しない** (`WindowPosition` と同じく、表示位置は別項目が持つ)。

## 6. 互換性・非機能

- **編集していないスクラップの表示・出力は v1.6 と完全に同一である。** これが本版の互換性の中核。
  変換パラメータがすべて既定値なら変換処理そのものを通さない (元画像をそのまま使う)。
- 変換適用後の画像は **`Freeze()` する** (CLAUDE.md の規約)。
  ウィンドウ・サムネイル・出力で使い回すため。
- **変換結果はキャッシュする。** パラメータが変わるまで再計算しない。
  拡大表示のたびに再サンプリングすると、キー連打で目に見えて重くなる。
- 大きな画像を 400% 表示するとメモリを消費する (4K 全画面を 400% で約 4 倍)。
  上限を 400% に置いた理由の一つでもある。実測して問題があれば上限を下げる。
- 混在 DPI 環境での付箋位置がズレないこと (`SPEC-v1.x.md` 4 の要件を維持)。

## 7. スコープ外 (M20 では実装しない)

| 項目 | 理由 |
|---|---|
| 任意角度の回転 | 90 度単位で用途を満たす。任意角度は余白の塗り方 (透過か単色か) を決める必要があり、判断が増える |
| 枠付きコピー / 枠付き保存 | 枠の種別が固定 (1px グレー) のため選ぶ意味が薄い。M21 (フレーム種別) と併せて扱う |
| 明るさ・コントラスト等の色調補正 | 「情報の一時保持」から外れる。画像編集ソフトの領域 |
| 文字・矢印の描き込み (注釈) | 同上。需要があれば独立したマイルストーンで検討する |
| 編集の undo / redo (多段) | 「編集をリセット」(2.6) で全戻しできる。多段履歴は永続化スキーマをさらに複雑にする |
| 拡大縮小率・キー移動幅の設定化 | 3 章参照。定数で始め、必要が確認できてから設定化する |

## 8. 決定事項

着手前に判断が必要だった項目 (`MILESTONES-v1.6.md` の「要判断」) は以下のとおり確定した。

| 項目 | 決定 | 根拠 |
|---|---|---|
| SPEC 4.4 (等倍・加工しない) の改訂 | 等倍は「不変条件」から「既定値」へ。編集は常にユーザーの明示操作 | 1 章。編集していないスクラップの挙動は変わらない |
| 元画像を保持するか | **非破壊** (元画像 + 変換パラメータ) | 2.1。劣化しない・取り消せる・画像ファイルを書き直さない |
| 編集結果を出力へ反映するか | **反映する** (コピー・保存・サムネイルすべて) | 2.8。「見えているものが取れる」。不透明度と枠線は従来どおり非反映 |
| 混在 DPI でのスケール基準 | **物理ピクセル基準** (100% = 物理ピクセル等倍) | 2.2。既存の物理座標配置をそのまま使え、等倍思想の延長 |
| 編集状態の永続化 | **する。`SchemaVersion` を 2 へ上げ、v1 は既定値で読む** | 5 章。編集は意図の強い操作で、失われると編集し直しになる |
| 拡大縮小の範囲 | **25%〜400%** | 2.2。下限はサイコロ領域との重なり、上限は誤操作対策 |
| 拡大縮小の操作 | キー (`Alt+↑↓`) とメニュープリセット。**ホイールは使わない** | 2.2。ホイールは不透明度に割り当て済みで、奪うと既存の操作体系を壊す |
| トリムの操作 | モード切替 (`T`) → 範囲選択 → `Enter` 確定 / `Esc` 取消 | 2.4。左ドラッグ移動との干渉を避ける。SETUNA2 の操作に合わせる |
