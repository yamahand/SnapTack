# SnapTack マイルストーン (v1.6〜) — SETUNA2 ギャップ埋め

MILESTONES-v1.5.md (M13〜M17) の続き。機能の根拠と優先度は `SETUNA2-gap-analysis.md` を参照。

> 作業ルール(CLAUDE.md)に従い、各マイルストーンは着手前に SPEC 追補
> (`SPEC-v1.6.md` 等)へ落とし込み、SPEC と矛盾する判断が必要なら選択肢を提示して確認を取る。
> 番号は v1.5 (M17) の続きとして M18 から採番する。

**v1.6 (M18 / M19) は仕様を `SPEC-v1.6.md` に確定させ、実装済み。**
M20 以降は**草案(proposal)であり、着手が確定した SPEC ではない**。

## リリース区切り

| リリース | マイルストーン | 内容 |
|---|---|---|
| v1.6 | M18 / M19 | 保存とコピーの強化 / スクラップの作成方法の追加 |
| v1.7 | M20 | スクラップの編集(拡大縮小・回転・反転・トリム) |
| v1.8 または v2.0 (**未定**) | M21 | スタイル機構 |

- 各リリースは独立して出荷可能とする。
- **M21 をどのリリースに載せるかは v1.7 完了後に判断する**。実装量が最大で、導入是非そのものが
  未決のため、先に決め打ちしない。

## 全体方針

SETUNA2 との差分の中核は **「画像編集」** と **「スタイル機構(自作スタイル + キー割り当て)」** の 2 つ。
SnapTack は後者の巨大な枠組みを一度に入れるのではなく、**まず価値の高い個別機能を足し**、
スタイル機構は必要性が固まってから最後に検討する(オーバーエンジニアリング回避)。

依存関係:

- M18 (保存強化) は既存の保存処理の拡張のみで、他に依存しない → **最初に着手可**。
- M19 (作成方法追加) も独立。M18 と順不同で、両方揃った時点で v1.6 とする。
- M20 (編集) は付箋のレンダリングに手を入れるため、単独の設計判断が要る → v1.7 に分ける。
- M21 (スタイル機構) は M20 までの機能を「スタイルの部品」として束ねる位置づけ。**最後**。

# v1.6

## M18: 保存とコピーの強化 ✅

**ゴール: SETUNA2 相当の保存/コピーの柔軟性を得る** — 仕様は `SPEC-v1.6.md` 2 章。

- [x] 保存形式の選択 (PNG / JPEG / BMP)。JPEG は品質指定
- [x] 即保存(日時で自動命名 → 指定フォルダへ、ダイアログ無し)。既存のダイアログ保存も残す
- [x] 保存先フォルダの設定項目(現行は `LastSaveDirectory` の記憶のみ)
- [x] 保存したファイルパスをクリップボードにコピーするオプション
- [x] 設定項目・UI 文字列 (`Strings.resx` / `.ja`) の追加

**確認**: 各形式で保存できる。即保存がダイアログ無しで指定フォルダに日時名で出る。JPEG 品質が効く。

> **要判断だった項目 → 決定済み** (`SPEC-v1.6.md` 2.2 / 6):
> 即保存は**付箋の右クリックメニュー + 付箋ローカルの `Ctrl+Shift+S`** とし、
> グローバルホットキーは追加しない(登録失敗リスクと設定項目を増やさず、対象が一意に決まるため)。

## M19: スクラップの作成方法の追加 ✅

**ゴール: キャプチャ以外からもスクラップを作れる** — 仕様は `SPEC-v1.6.md` 3 章。

- [x] クリップボード画像からスクラップ作成(トレイメニュー)
- [x] クリップボード内テキストが画像ファイルパスならその画像から作成
- [x] webp / avif の読み込み対応(WIC のデコーダで追加コスト無し。`SPEC-v1.6.md` 3.2)
- [x] 画像ファイルの D&D でスクラップ作成
  - [ ] exe / トレイアイコンへのドロップ → **スコープ外** (`SPEC-v1.6.md` 3.5)
  - [x] スクラップリストウィンドウへのドロップ
- [x] 作成経路が増えても `ScrapManager` の一元管理を崩さないこと(生成は必ず Manager 経由)

**確認**: 画像をコピー→貼り付けで付箋化。png/jpg/bmp をドロップして付箋化。作られたスクラップが
リストにも載り、永続化される。

> **要判断だった項目 → 決定済み** (`SPEC-v1.6.md` 3.4 / 6):
> 外部画像の `PhysicalRect` は**カーソル位置を左上**とし、はみ出す場合はそのモニタ内へクランプする。
> サイズは画像の物理ピクセル等倍(大きくても縮小しない)。
>
> **exe / トレイアイコンへのドロップは本版のスコープ外**とした。exe へのドロップは
> 二重起動時の挙動 (SPEC 4.1) の変更と既存プロセスへの IPC が必要で、実質コマンドライン対応と
> 同じ設計判断になるため。コマンドライン対応と併せて別途検討する。

# v1.7

## M20: スクラップの編集(拡大縮小・回転・反転・トリム)

**ゴール: 貼った後にスクラップを加工できる**

- [ ] 拡大縮小(スケール指定。SETUNA2 同様、拡大は上限を設ける)
- [ ] 回転 (90/180/270) と反転(水平/垂直)
- [ ] トリム(付箋上で範囲を再選択して切り出し)
- [ ] キー移動(1px / 50px)と移動値の数値表示
- [ ] 編集結果を保存/コピーへ反映するか、元画像を保持するかの方針決定
      (SETUNA2 は「枠付き/枠なし」を出力時に選べる。SnapTack の等倍思想との整合を要検討)
- [ ] 編集状態を永続化するか(`index.json` のスキーマ拡張が要るか)の判断

**確認**: 拡大縮小・回転・反転・トリムが付箋に反映される。編集後もコピー/保存が正しい。

> **要判断(SPEC 4.4 と衝突)**: `SPEC.md` 4.4 は「付箋は物理ピクセル等倍・加工しない」と定めており、
> M20 はこの前提を崩す。`SPEC.md` 6章に見直しが必要な旨は記載済みだが、**具体的な改訂内容は
> 着手時に追補 (`SPEC-v1.7.md` 想定) で定義し、その内容をユーザーに確認する**。
> 混在 DPI 環境でのスケール基準(物理px か DIP か)も要決定。

# v1.8 または v2.0(未定)

## M21: スタイル機構(最後・任意)

**ゴール: 外観/加工/出力の組み合わせをスタイルとして保存し、キーを割り当てる**

SETUNA2 の設計の核。ただし M18〜M20 を個別機能で満たせれば **必須ではない**。
需要が確認できてから着手する。**どのリリースに載せるかは v1.7 完了後に判断する。**

- [ ] フレーム種別(ウインドウ枠 / 単色枠(色・太さ) / 立体枠 / 枠なし)
- [ ] ウインドウタイプ(Topmost off・タスクバー格納可)への切替
- [ ] スタイル = 上記 + 不透明度 + スケール等の組み合わせを名前付きで保存
- [ ] スタイルへの任意ショートカットキー割り当て(複数可)
- [ ] 右クリックメニューへのスタイル追加・並べ替え・削除
- [ ] 「基本スタイル」「Wクリック時スタイル」の指定

**確認**: 自作スタイルを作り、キーで即適用できる。ダブルクリック時のスタイルが効く。

> **要判断**: SnapTack はここまで固定 UI・固定キーで通してきた(`SPEC-v1.x` 4「操作体系は変更しない」)。
> スタイル機構は設定 UI・永続化スキーマ・ホットキー登録数を大きく増やす。
> **導入是非そのものをユーザー判断とする。** 個別機能 (M18〜M20) で足りるなら見送る選択もあり。
> メジャーバージョン (v2.0) を名乗るだけの変更幅があるかも、この判断材料になる。
